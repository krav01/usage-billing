# Usage Billing v0.3.0 — release preparation

Unreleased: this document prepares the next portfolio release. It does not
announce a published tag, prebuilt binary, or deployment.

## Changes since v0.2.0

- Durable quarantine after three confirmed ledger integrity failures, with
  generation-checked manual retry and unchanged frozen-price replay.
- Full-row backup/restore verification and processing from a new database.
- Server-generated HTTP request IDs, structured safe logs, and durable original
  acceptance IDs through PostgreSQL, worker processing, replay and retry.
- A populated schema-v2-to-v3 upgrade drill using a newly created CI database,
  including old recovery state, changed-price replay and API restart.

## Upgrade and compatibility

Apply migrations `000002` and `000003` in order before starting this version.
Stop older workers first, especially code that predates quarantine. Follow the
[upgrade procedure](../UPGRADING.md) with retained demo credentials.

Event responses add optional read-only `request_id`; producer input cannot set
it. Historical rows omit it. The response header describes the current HTTP
attempt; the body retains the original acceptance ID. New code adds no runtime
dependencies. The original worker `ProcessBatch` contract remains available.

Binary rollback should retain schema v3. Guarded down migrations refuse to erase
correlation or active recovery state. See [event recovery](../EVENT_RECOVERY.md)
and [operations](../OPERATIONS.md) for exact semantics.

## Verification and limits

Before publishing, require successful Go/race/lint/security, PostgreSQL integration,
migration, Docker smoke, upgrade, crash recovery, backup/restore and monitoring
checks on the release source. The PR and Actions history provide commit-specific
results; this note does not claim that a future release has passed.

This remains an isolated educational service with one trusted-producer token.
No real payments, invoices, tenant authorization or public deployment. Worker logs
are diagnostic: a crash after commit can lose a log line. Existing load samples
are finite observations, not sustained capacity guarantees.

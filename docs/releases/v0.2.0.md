# Usage Billing v0.2.0

My second portfolio release extends the Go/PostgreSQL usage ledger with bounded
admission, failure-recovery evidence, and a reproducible monitoring demo.
This remains an educational service, not a payment processor.

## Added since v0.1.0

- A bounded full-service load client using real HTTP, PostgreSQL, and the worker.
  CI records three 500-event, eight-client runs and checks exact settlement.
- Authenticated durable queue gauges and process-local worker counters with
  fixed-cardinality labels.
- A coordinated PostgreSQL process-crash test during an unfinished worker
  transaction, followed by recovery without restarting the API or duplicating
  the tested ledger entries.
- A configurable pending-event limit, transactional rejection, HTTP `503`
  (`queue_full`) with `Retry-After`, and replay availability when the queue is full.
- Exponential worker retry backoff with a bounded delay and prompt cancellation.
- Optional localhost-only Prometheus/Grafana, six provisioned panels, five demo
  alerts, promtool rule tests, and live provisioning/authentication checks in CI.

The worker error-ratio example now handles fewer than one attempt per second
correctly. Monitoring uses ignored local file-backed secrets to retain read-only
container root filesystems. Secrets are excluded from Docker build contexts as
well as Git; no extra Go module dependencies were introduced.

See the dated [verification record](../VERIFICATION.md) for the feature commit's
CI runs and the exact assertions exercised.

## Compatibility and demo

Existing event/summary paths and frozen-price replay semantics remain unchanged.
No database migration is added. New admissions now default to a 10,000-event
pending limit; producers must handle `503` with bounded retries using the same ID.
All API instances must use the same admission policy. Lowering the limit does not
discard existing pending events.

Follow the [guided demo](../DEMO.md), [monitoring setup](../MONITORING.md), and
[failure scenario](../RESILIENCE.md). The base Compose stack still runs without
monitoring. Images are built from source; no prebuilt release binaries are supplied.
Keep existing volume credentials when restarting or upgrading a local demo.

## Deliberate limits

One trusted-producer token, no tenant-level authorization, invoices, taxes,
payments, production deployment, or external alert delivery. Queue admission
serializes new events; retry backoff has no jitter or poison-message quarantine.
The crash test does not cover permanent disk loss or multi-node failover.
Load results are finite closed-loop observations, not sustainable capacity or SLOs.
